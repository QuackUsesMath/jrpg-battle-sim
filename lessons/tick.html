Ticks and ATB bars

Lesson 1 · Mission: build your own turn-based battle game in C, running in the terminal

Your win for this lesson: by the end you can read a small C program and predict on which tick each fighter becomes ready to act.

1. The idea in three sentences

A tick is one step of the game's clock. Every combatant has a gauge, which is just a number. On every tick, each gauge goes up by that combatant's speed, and when a gauge reaches the maximum, that combatant may act and the gauge drops back down.

That is the whole ATB (Active Time Battle) bar. The coloured bar on screen is only a picture of one integer.

2. What FF5 actually does (verified)

  • Time keeps flowing for both you and the enemies, and each character has a visible bar that fills according to speed. Wikipedia: Final Fantasy V
  • Haste makes a bar fill in half the time, so think "speed × 2". FF Wiki: Haste (FFV)
  • Equipment weight reduces agility, which slows the bar. FF Wiki: FFV stats

The exact internal numbers FF5 uses were not checked for this lesson. Everything below is a simplified model that behaves the same way, which is exactly what you need for your own game.

3. Play with it

Each tick, every gauge gains its speed. Reaching 100 means ready. Try making Faris much faster than Lenna, then turn Haste on.

4. The same thing in C

Save as ticks.c, then build and run with gcc -std=c99 -Wall ticks.c -o ticks && ./ticks

#include <stdio.h>

#define GAUGE_MAX 100

typedef struct {
    const char *name;
    int speed;
    int gauge;
} Combatant;

void tick(Combatant *c) {
    c->gauge += c->speed;      /* one tick of time passes */
}

int main(void) {
    Combatant party[3] = {
        {"Bartz", 8, 0},
        {"Lenna", 6, 0},
        {"Faris", 10, 0}
    };

    for (int t = 1; t <= 40; t++) {
        for (int i = 0; i < 3; i++) {
            tick(&party[i]);
            if (party[i].gauge >= GAUGE_MAX) {
                printf("tick %2d: %s is ready!\n", t, party[i].name);
                party[i].gauge -= GAUGE_MAX;
            }
        }
    }
    return 0;
}

Three things to notice:

  • struct bundles one fighter's data in one place, so adding a field like hp later is easy.
  • tick(&party[i]) passes the address of the fighter. Inside, c->gauge means "the gauge of the struct that c points to". Without the pointer, C would hand tick a copy and your change would vanish.
  • gauge -= GAUGE_MAX instead of gauge = 0 keeps any overflow. Bartz hits 104 on tick 13 and restarts at 4, which keeps his timing fair over a long fight.
